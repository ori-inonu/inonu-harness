# Inonu Harness

Use the local runner for opt-in, read-only diagnosis and explicit SDD support. Keep the normal eight-stage workflow: Constitution, Research, Specification, Planning, Tasks, Implementation, Review, and Convergence. Inonu supplements those stages; it does not replace the host, authorize actions, or run paid services automatically.

## Commands

From the repository root, use `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py"`:

- `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py" check [--root PATH] [--ref REF]` compiles and tests the checkout (or `--root`) and prints a JSON summary. With `--ref`, it verifies that commit in a temporary export instead and adds a `runner` step; commit first, then run it with `--ref HEAD` before pushing. It covers this operating system only, and a pass does not show that the plugin installs. Run it before convergence; a pass is deterministic evidence for those steps, not proof of semantic correctness.
- The `versions` step of `check` fails when the stated package versions differ in `inonu_harness/__init__.py`, `pyproject.toml`, `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` (the last one only when it states a version). It also fails when one of those files cannot be parsed or has no version, or when a stated version is outside the 0.MINOR.PATCH scheme. A release edits those files together; the step only compares them and changes nothing.
- `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py" version --scheme` checks that the stated versions agree and that each one is a milestone version `0.MINOR.PATCH` (each part 0 to 99); `version --next` prints the next milestone's version from the one the manifests state. Both read files only. Milestone `n` is `0.(n // 100).(n % 100)`, and `1.0.0` is the owner's decision. See the [versioning guide](../../docs/versioning.md).
- `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py" bundle plan [--host codex|claude|both] [--home PATH]` prints a read-only JSON plan of the full bundle. It applies nothing; hook, MCP and agent installation need owner authorization.
- `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py" bundle status [--host codex|claude|both] [--home PATH]` reports read-only the state of each planned item (`current`, `absent`, `configured`, `unknown` and similar). `configured` means the host file has the key, not that the server is reachable. Each item also has an `ownership` (`ours`, `modified` (also when the user deleted it), `foreign`, `none` or `unknown`) from the bundle's ledger; it is advisory and read-only and changes nothing that `apply` or `remove` does.
- `bundle apply [--host ...] [--home PATH] [--with-stop-hook] [--apply]` and `bundle remove` with the same flags: preview by default, and write only with `--apply` and the owner's authorization. The stop hook is opt-in. Remove reverses only unchanged, ledger-owned items; conflicts are kept.
- `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py" hook trust [--root PATH] [--home PATH] [--yes]` previews, and with `--yes` records trust of, the project's `.inonu/verify.json` by its SHA-256; `hook untrust` removes that record. `hook stop` is the Stop hook entry that `bundle apply --with-stop-hook` registers: it runs only a trusted config and exits 2 to block a stop on a failing check. Trust is the owner's decision, so do not pass `--yes` on the owner's behalf. See the [hook reference](../../docs/hook.md).
- `doctor [--project-root PATH]` prints a sanitized JSON inventory. Use `--project-root` when diagnosing a selected project from an installed global skill; omit it to inspect this checkout.
- `baseline run FIXTURE` runs a local offline fixture; `baseline compare BEFORE AFTER [--max-regression R]` compares saved JSON results and, with the flag, adds a regression gate (exit 0 pass, 1 fail, 2 incomparable) over two saved local measurements. It does not establish agent quality.
- `decisions --db PATH create ID --question TEXT --alternatives JSON --criteria JSON --idempotency-key KEY` records a pending decision in a local SQLite store. The decision remains pending until explicit evidence-backed authorization is recorded.
- `decisions --db PATH context --ids ID...` reads only explicitly selected decisions. `decisions --db PATH packet --task-file PATH --ids ID...` validates a task file and combines it with those decisions. Review outputs before attaching them to a task; neither command injects prompts.
- `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py" decisions --db PATH context|packet ... --refuse-secret-patterns` adds an opt-in check to either command. On a match of a short list of credential formats it prints nothing to stdout, names only the rule and path on stderr and exits 2. Pass it whenever the output goes to an agent. It misses passwords in prose, custom tokens and most other formats, can raise false positives, and never prints a matched value. Without the flag the output is unchanged.
- `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py" decisions --db PATH as-of TIMESTAMP [--ids ID...]` prints each decision as it was at a timestamp with an explicit offset or `Z`, read from its revision history; the database is opened read-only. A decision created later is `not_yet_created` when named with `--ids`. The times come from the recording machine's clock and are not authenticated, so this is a local audit aid, not a tamper-proof ledger; it cannot show a state before the first revision. It changes no schema.
- `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py" decisions --db PATH ready` lists pending decisions whose declared dependencies are all authorized (`ready`), and pending decisions still waiting on others (`waiting`, with each unauthorized dependency and its status, `missing` when absent). The database is opened read-only and its file is not modified. Ready means only that the decision's own direct dependencies are authorized: it does not authorize, claim or schedule the decision. The output includes the decision text and does not scan for credentials, so review it before attaching it to an agent.
- `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py" jev spec --decision PATH --doc PATH [--doc PATH ...] [--root DIR] [--max-facts N]` prints a Jev decision spec whose facts are each document's own text, in chunks of at most 300 characters, after a source fact with its path and digest. It calls no Jev and writes no file. It exits 2 without a document, for a document outside the root or one that matches its secret patterns (short list; keep credentials out of documents), for an unknown key in the decision, and when the facts exceed `--max-facts`. The document must describe the problem, not state the answer, and the command cannot check that. Pass its output to `consensus_plan` and then `consensus_run`, not a hand-written summary.
- `sdd audit MANIFEST [--root ROOT]` checks declared local artifact links and hashes. It does not run checks or prove their meaning.
- `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py" loop run SPEC.json` repeats a caller-chosen `step` command under mandatory limits and stops only on verifier exit codes. It runs the commands listed in the spec and writes a JSONL log, but never calls a model; the step's cost is the caller's. See the [loop reference](../../docs/loop.md).
- `python "${CLAUDE_PLUGIN_ROOT}/scripts/inonu.py" docs lint [--root PATH] [--max-bytes N] [--max-lines N]` checks the instruction files (`AGENTS.md`, `AGENTS.override.md`, `CLAUDE.md`) for size, `@path` imports and UTF-8, every `SKILL.md` below `skills/` for size (under 20,000 bytes and 500 lines) and links, and checks links in `README.md` and the Markdown under `docs/`. It prints one JSON object, writes nothing and exits 0 for `pass`, 1 for `fail` or 2 for invalid input. Follow each finding's `remediation`; it checks links and size only, not whether documents are true or current.

Keep real money, credentials, authentication, risk limits, migrations, billing, and other protected actions behind their required human approval. Recommendations and stored decisions never grant permission.

See the [SDD workflow](../../docs/sdd-workflow.md) and [benchmark plan](../../docs/benchmark-plan.md) for the existing process and evidence limits. The [plugin reference](../../docs/plugin.md) explains installing this repository as a Claude Code plugin; that package has not been checked with `claude plugin validate`.
