# v0.0.6 plan — D01/D02 offline evaluation design

This plan captures the proposed design only. The current authorized increment is documentation; it does not create or execute fixtures, modify code, call live models or services, install or adopt tools, or implement a router.

1. **D01 corpus proposal:** define five sanitized case intents and expected eight-stage traces in [spec.md](spec.md). Use existing baseline and SDD-context fixtures only as local format references.
2. **D02 rubric proposal:** define mandatory per-fixture pass/fail gates, evidence references, the sole justified `N/A` case, a complete case-level claim ledger for material claims in `input_intent`, all eight stages, expected/observed outcomes, and gate evidence, plus the separate qualitative note record in [spec.md](spec.md). Preserve the runner's limits: it records supplied acceptance outcomes and does not judge traces.
3. **D03 candidate-scope decision:** locally select the artifact-handoff contract for static validation: check requirement-to-specification-to-task-to-verification traceability. This is a scope choice, not evidence that the practice improves agent outcomes.
4. **Later authorized fixture work:** only after a separate explicit authorization, create the five synthetic case records. These are test inputs, not traces observed from agent sessions. Tests must validate exact claim-ledger coverage for `input_intent`, each expected/observed stage, expected/observed outcomes, and every gate evidence reference. Include negative cases where an input claim or gate-evidence claim is omitted, as well as missing, duplicate, orphaned, unclassified, or unresolved required references. Validate those and the case expectations before computing gate outcomes. Then build a complete in-memory baseline v1 mapping with every required field before calling `run_fixture(...)`. A CLI-seam test writes that same valid mapping to a temporary JSON file and invokes `baseline run`; case records are not passed directly to the baseline parser. Keep justified `N/A` reasons outside the baseline v1 acceptance array; do not compare measured duration or Python/component versions.
5. **Later offline recording and review:** validate test-supplied synthetic trace entries and material claim ledgers against frozen expectations, pass computed gate outcomes through the existing baseline runner, retain evidence per case, and keep reviewer notes separate. This establishes only static contract integrity; it does not measure real-agent effectiveness. Do not aggregate scores or claim live-agent quality or productivity.

The later tasks in [tasks.md](tasks.md) remain blocked until their stated authorization and dependencies are satisfied. This plan does not claim that the practice was evaluated, that agent outcomes improved, or that the milestone converged.
