# v0.23.0 — Jev decisions grounded in a document

The Jev judge decides only from the decision object it is sent: `goal`, `facts`, `rails` and `options`. It reads no repository, no spec file and no conversation ([v0.22.0 decisions](../v0.22.0/decisions.md) D4). Until now the coordinator wrote the facts by hand as a summary, so every scope decision from 0.10.0 to 0.21.0 rested on that summary. The owner asked that a decision never reach the judge without a specification document that gives it the project's context. This milestone adds a deterministic command that turns documents into the `facts` of a decision spec, so that the context is the document's own text and the rule can be checked. The scope was set by the owner ([decisions.md](decisions.md)).

## Requirements

- R1 `python -m inonu_harness jev spec --decision FILE --doc PATH [--doc PATH ...] [--root DIR] [--max-facts N]` prints one JSON object on stdout: a Jev decision spec ready to pass as `spec` to `consensus_plan` and then `consensus_run`. The output is compact, ASCII-escaped and ends with a newline. The command does not call Jev, does not decide anything and writes no file.
- R2 `--decision FILE` is a JSON object with `id`, `goal`, `rails` and `options`, and optionally `forbidden`, `unknowns` and a `facts` object of the author's own scalar facts. It is read as UTF-8 (a leading byte order mark is accepted) and may not exceed 64 KiB. Any other top-level key is refused, so a misspelled `forbidden` cannot vanish. At least one `--doc` is required: without a document the command exits 2, which is how the rule "no Jev call without a document" is enforced.
- R3 Each `--doc` is resolved against `--root` (default: the current directory). It must be a regular file, not a symbolic link, inside the root after resolution, valid UTF-8 without NUL characters, and at most 64 KiB. Its last path component may not contain a colon (an NTFS alternate data stream). The same file may not be given twice, under another spelling or through a hard link. A document with no text after collapsing is refused, and a leading byte order mark is dropped. Documents keep the order given.
- R4 Facts are generated in document order. For document N (counting from 1) there is a fact `docN_source` holding the path relative to the root, in forward slashes, a space and `sha256:` plus the first 16 hex digits of the file's SHA-256, then `docN_001`, `docN_002` and so on. A key in the decision's own `facts` that matches `doc<digits>_...` is refused, so the generated keys never collide.
- R5 Chunking is deterministic and keeps the text: lines are read in order (a lone carriage return ends a line), whitespace inside a line is collapsed to single spaces, blank lines are dropped, and consecutive lines are packed into one fact separated by a newline while the fact stays within 300 characters. Length is counted as the judge counts it, in UTF-16 code units, so an emoji counts 2; `_validate_spec` counts the same way. A line longer than 300 characters is split at the last sentence end (`. `) whose full stop is at index 60 or later, else at the last space, else at the limit (never between a letter and its combining mark), and the rest continues in the next fact. Nothing is summarized, reordered or left out: removing all whitespace from the facts of a document and joining them gives the same characters as removing all whitespace from the document.
- R6 The whole spec is checked with the existing `_validate_spec` of `inonu_harness/jev.py` (limits and the sensitive-content scan). A violation exits 2 with a fixed message that never echoes document or decision text. Before that, the whole collapsed text of each document is scanned, so that a secret split by a fact boundary is still seen. The scan uses the validator's patterns and a short list of common token formats (GitHub, AWS, Slack and Google keys, bearer tokens, JWTs, PEM private-key headers). A message can name the document (`document 2 contains a sensitive value`) but not the text. The scan cannot recognize every secret.
- R7 `--max-facts` defaults to 80. When the documents would need more facts than the limit, the command exits 2 and states the count and the limit; it never truncates.
- R8 Output is a pure function of the inputs: the same decision, documents and options give the same bytes.
- R9 Tests cover:
  - chunk boundaries at 299, 300 and 301 characters, joining chunks back into the collapsed text, a long line with sentence ends, with only spaces and with no space at all, and non-ASCII text under a strict ASCII stdout;
  - the source fact and its digest, document order, keys that do not collide, and a refused `doc1_001` in the decision's own facts;
  - exit 2 without `--doc`, with a missing file, a directory, a symbolic link (skipped where the host cannot make one), a path outside the root, a duplicate, non-UTF-8, a NUL character, an oversized file, an invalid decision file and an oversized decision file;
  - a planted credential-looking string refused without being echoed, a fact or option over its Jev limit refused, and `--max-facts` exceeded;
  - determinism, and that nothing is written;
  - that the output passes `_validate_spec` and that `JevAdapter` with `MockJevTransport` accepts it.
- R10 Docs: CHANGELOG 0.23.0, README, `docs/sdd-workflow.md` (the Portuguese section on bounded decisions), `docs/integrations.md` (the Jev section: what the judge sees, the limits, the generic `internal error`) and a skill bullet. They state the rule, the command, that the brief must not state the answer, and what the command does not do. Version 0.23.0 in `inonu_harness/__init__.py`, `pyproject.toml`, `.claude-plugin/plugin.json` and the version assertions in the tests.

## Out of scope

Calling Jev from the CLI (the host MCP transport is not portable), summarizing documents, judging whether a brief leaks its answer, re-running earlier milestones' decisions, and recording receipts in the Decision Graph.
