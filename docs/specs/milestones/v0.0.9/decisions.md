- Official [Codex skill discovery](https://learn.chatgpt.com/docs/build-skills) supports user `.agents/skills`; [Claude skills](https://code.claude.com/docs/en/skills) supports user `.claude/skills`. [Settings precedence](https://code.claude.com/docs/en/settings) distinguishes local user configuration from repository configuration.
- A fresh configuration inventory is kept out of public files. Claude Code is present in the official Anthropic VS Code extension even though its CLI is not on PATH. Existing local binaries and official command help are used for discovery and setup.
- The public profile installer adds only its own skill and local ownership metadata. Native skill discovery avoids rewriting unrelated global instructions. Installation previews and idempotence/conflict checks protect existing user files.
- Shell rendering is host-specific because the current Codex uses PowerShell and Claude Code uses Bash on Windows. Source instructions remain portable; rendered private paths stay outside Git.
- Inonu complements the existing tools. Source and deterministic tests show its current capability boundaries; no real-task benchmark establishes that it replaces their combination. A registration or MCP handshake is not proof of model-session use or performance gains.
- Publication target is the existing `codex/m0-inonu-harness` branch. The default branch is not changed or merged implicitly. Public release artifacts omit local config snapshots, private paths and logs.
