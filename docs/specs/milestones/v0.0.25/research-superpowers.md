## Summary

obra/superpowers (HEAD 2ce8aa1, plugin version 7.0.1, MIT) is a skills library. Its chain runs brainstorming (approval hard gate), then writing-plans, then executing-plans (inline) or subagent-driven-development (fresh subagent per task), then finishing-a-development-branch. Specs and plans are dated Markdown under docs/superpowers/. A plan header carries Spec, Global Constraints and Review Focus; tasks are Task N blocks with checkbox steps. Execution state lives in a git-ignored per-plan ledger (.superpowers/sdd/slug/progress.md) with fixed line shapes. A task completes when its test command exits 0 and its reviews pass. Ruling lines replace stops during execution. There are no milestone units and no requirement IDs. Gates are prose plus five bash helpers. Static reading only; no script was run.

## Lifecycle

1. **1. Brainstorm the request and approve the design** — skills/brainstorming (agent with human partner); lays out approaches, then writes the design doc. Inputs: user request; repo files read first (Look Before You Ask); builder check subagent result. Outputs: approaches message; docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md (or a short doc in chat for a small change). Gate: partner approves the design doc (HARD-GATE, brainstorming lines 247-261); a spike needs an explicit yes.
2. **2. Split large work into independent plans** — brainstorming Size the Work; writing-plans Scope Check. Inputs: spec covering several subsystems or projects. Outputs: one spec and one plan per independent subsystem, in an agreed order. Gate: partner agrees the order (brainstorming lines 204-206).
3. **3. Isolate the workspace** — skills/using-git-worktrees Steps 0-3. Inputs: branch name; GIT_DIR and GIT_COMMON state. Outputs: linked worktree or in-place work; baseline test report. Gate: consent in a plain repo (lines 41-45); baseline tests pass or the partner decides.
4. **4. Write the plan and self-review it** — skills/writing-plans. Inputs: approved spec path. Outputs: docs/superpowers/plans/YYYY-MM-DD-<feature>.md with header, Global Constraints, Review Focus and Task N blocks. Gate: self-review of spec coverage, step scan, type consistency, Review Focus and proportion (lines 163-177); no subagent used.
5. **5. Choose the executor** — writing-plans Execution Handoff. Inputs: plan file. Outputs: chosen method: subagent-driven-development or executing-plans, named as REQUIRED SUB-SKILL. Gate: partner reviews the plan and picks the method (lines 179-204).
6. **6. Set up the plan workspace, ledger and pre-flight** — sdd-workspace PLAN_FILE; executing-plans Setup; test-driven-development loaded; preflight table. Inputs: plan; spec named in the plan header. Outputs: .superpowers/sdd/<slug>/progress.md with identity line; pre-flight rows; Ruling lines for conflicts. Gate: ledger resume check (complete lines are skipped); pre-flight table written before Task 1.
7. **7a. Per task, subagent-driven path** — task-brief; implementer subagent (implementer-prompt.md); review-package; task-reviewer-prompt.md; fix loop (fix-loop.md). Inputs: brief path; BASE sha recorded before dispatch; report file path. Outputs: task-N-report.md; review-<base7>..<head7>.diff; ledger line 'Task N: complete (review clean)' or '(K parked)'. Gate: spec compliant and quality approved, or every open finding parked with a ruling at the 5-round cap.
8. **7b. Per task, inline path** — executing-plans scripts task-start PLAN N, then TDD steps, then task-done PLAN N BASE -- TEST_CMD. Inputs: brief text; BASE from task-start. Outputs: ledger line 'Task N: complete (commits base7..head7, tests: cmd → last line)'; task-N-tests.log. Gate: test command exit 0; each Expected line compared; each deviation has a Ruling line (executing-plans lines 207-220).
9. **8. Whole-branch final review and one fix pass** — review-package PLAN MERGE_BASE HEAD; requesting-code-review code-reviewer.md on the most capable model. Inputs: branch diff; plan; spec; Review Focus; ledger minor and parked lines. Outputs: findings; 'Final: minor (deferred)' lines; one fix wave with 'Final: fixed ... RED→GREEN' lines. Gate: Critical and Important fixed in one pass; residual findings surfaced to the partner, no second fix wave (final-review lines 17-29).
10. **9. Delete the plan workspace** — controller (rm -rf of the plan directory only). Inputs: clean final review and merged fix wave. Outputs: no workspace; git history is the record; Rulings list and Deferred minors in the final message. Gate: final review clean (executing-plans lines 293-302; final-review lines 31-47).
11. **10. Finish the branch** — skills/finishing-a-development-branch. Inputs: green full test suite; base branch confirmed. Outputs: merge, pushed PR, or kept branch; worktree removed only after merge or typed discard. Gate: partner chooses one of the options; discard requires the partner to type 'discard' (lines 132-146).

## Numbering rules

- Plan files: date prefix YYYY-MM-DD and a kebab-case feature name (writing-plans SKILL.md line 16).
- Design docs: date prefix, kebab-case topic, suffix -design by convention (brainstorming SKILL.md lines 224-226; 20 of 22 files in the repo follow it).
- Task numbers: integer N in '### Task N:' headings; steps are checkbox items 'Step N' restarting within each task (writing-plans lines 95, 108).
- Task file names: task-<N>-brief.md, task-<N>-report.md, task-<N>-tests.log in the plan workspace.
- Workspace slug is the plan basename without .md; collisions get the parent directory name, then -2, -3 (sdd-workspace lines 41, 73-82).
- Review package names use short SHAs: review-<base7>..<head7>.diff (review-package line 36).
- Fix rounds are numbered R/5 with a maximum of five per task; rounds 1-3 resume, 4-5 escalate (fix-loop lines 21-34, 54).
- Ledger keys are BASE and HEAD short SHAs; BASE is never HEAD~1 in the executors' rules (SDD line 241; executing-plans line 205).
- Ledger prefixes: 'Task N:' for per-task events and 'Final:' for whole-branch events (executing-plans lines 272, 281; SDD lines 310-312).
- Ruling format is three fields separated by em dashes: decision, why, cost if wrong (SDD lines 22-23).
- Release versions are MAJOR.MINOR.PATCH in manifests (7.0.1) and headings 'v7.0.1 (date)'. There is no milestone or v0.0.N numbering in this repo.

## Adoption candidates (reader's)

- **Requirement-ID coverage check between spec and tasks** (effort M; relates to F05, F06). Adopt: Give each spec requirement a stable ID (Inonu milestones already use R1..Rn) and have every task name the IDs it satisfies. Superpowers only checks coverage by manual self-review (writing-plans lines 163-177) and a prose Review Focus list with no IDs, so coverage is judged by reading.
