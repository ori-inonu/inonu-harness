## Summary

GSD checks its own work with prompt-defined agents over a thin deterministic CLI. The verifier starts from roadmap success criteria and PLAN must-haves, presumes failure, and returns passed, gaps_found or human_needed. Stub detection, the test-quality audit and scope-reduction checks are grep patterns and rules written into prompts, not code. verify.cjs checks line counts, substrings, regex key links and a self-check text the executor wrote itself. Safety rails are mostly advisory hooks: the prompt-injection guard, read-before-edit guard and read injection scanner install by default, while workflow and commit guards need config. The repo's own CI runs lint gates, a three-OS test matrix and a diff security scan. The repo is archived. Static reading only; nothing was executed.

## Lifecycle

1. **Plan authored** — gsd-planner via plan-phase. Inputs: ROADMAP success criteria, CONTEXT.md decisions, REQUIREMENTS.md. Outputs: Plan files with must_haves frontmatter and task blocks. Gate: None at authoring; checked in the next steps.
2. **Post-planning gap check** — get-shit-done/bin/lib/gap-checker.cjs. Inputs: REQUIREMENTS.md, per-phase CONTEXT.md, plan text. Outputs: Source, Item, Status table for REQ and D IDs. Gate: Gated by workflow.post_planning_gaps (default true); when disabled returns enabled false.
3. **Plan check** — gsd-plan-checker, spawned by plan-phase. Inputs: Plans, ROADMAP criteria, CONTEXT.md, VALIDATION.md. Outputs: VERIFICATION PASSED or ISSUES FOUND with blocker, warning and info items. Gate: Any blocker sends plans back to the planner; revision loop capped at 3 with early escalation when issues do not fall (references/gates.md 18-24).
4. **Task execution** — gsd-executor via execute-phase or execute-plan. Inputs: Plan tasks, CLAUDE.md directives. Outputs: One commit per task; deviations recorded in SUMMARY. Gate: MVP+TDD gate halts behavior-adding tasks without a RED commit when both modes are on; destructive-git prohibition in worktrees.
5. **Executor self-check** — gsd-executor self_check step. Inputs: SUMMARY.md draft, created files, commit hashes. Outputs: Self-Check PASSED or FAILED section in SUMMARY.md. Gate: Do not update STATE.md if FAILED (agents/gsd-executor.md line 658).
6. **Phase verification** — gsd-verifier via verify-phase. Inputs: ROADMAP criteria, PLAN must_haves, source, tests, SUMMARY. Outputs: VERIFICATION.md with status, score and gaps. Gate: Decision tree: gaps_found beats human_needed beats passed (verify-phase.md 461-473); anti-pattern scan, test-quality audit, spot-checks and probes run first.
7. **Gap closure (inferred)** — verify-phase generate_fix_plans step, then a planner in gap-closure mode (planner-gap-closure.md not read). Inputs: Gaps list from VERIFICATION.md. Outputs: Fix plans. Gate: Re-verification after fix plans run (inferred from the step order).
8. **User acceptance testing** — verify-work with the developer. Inputs: SUMMARY.md (pre-flight: blocked when missing, gates.md line 55). Outputs: *-UAT.md with per-test results and Gaps. Gate: Any issue escalates to the developer; severity inferred from the user's wording.
9. **Debug on failure** — /gsd:debug, then gsd-debug-session-manager, then gsd-debugger. Inputs: User symptoms, knowledge-base.md. Outputs: .planning/debug/slug.md; knowledge-base entry on resolve. Gate: CHECKPOINT REACHED returns to the user; resolution only after awaiting_human_verify.
10. **Milestone audit** — audit-milestone workflow with gsd-integration-checker. Inputs: Every phase VERIFICATION.md, REQUIREMENTS traceability, SUMMARY frontmatter. Outputs: v{version}-MILESTONE-AUDIT.md with passed, gaps_found or tech_debt. Gate: Any unsatisfied requirement forces gaps_found (audit-milestone.md line 137).
11. **Commit** — gsd-sdk query commit for planning files; git hooks for code. Inputs: Staged files, commit message. Outputs: Commit, or a skipped result with reason. Gate: commit_docs and gitignore checks; opt-in Conventional Commits hook; CI diff scans and Tests on pull requests.
