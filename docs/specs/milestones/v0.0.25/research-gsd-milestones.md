## Summary

GSD runs milestones as markdown workflows (commands/gsd/*.md wrapping get-shit-done/workflows/*.md) backed by a deterministic CLI and SDK (gsd-sdk query, get-shit-done/bin/lib/milestone.cjs, phase.cjs). Milestone ids are free-form v&lt;major&gt;.&lt;minor&gt; strings chosen by the user. Integer phases continue across milestones unless --reset-phase-numbers is passed; inserted phases are decimal N.M. The lifecycle is new-milestone (REQ-IDs, roadmapper), execution (REQ ids flow from plan frontmatter to summary to REQUIREMENTS.md), audit-milestone (three-source matrix, gaps_found), gap-closure phases, then complete-milestone (archive, MILESTONES.md, optional git tag). Main risk: new-milestone clears phase directories before its reset-safety step. Static reading only; all lines pinned to HEAD bdcaab2c.

## Lifecycle

1. **Start: /gsd:new-milestone with optional name, --reset-phase-numbers and --text** — commands/gsd/new-milestone.md, then workflow Step 1. Inputs: $ARGUMENTS, PROJECT.md, MILESTONES.md, STATE.md, optional MILESTONE-CONTEXT.md. Outputs: parsed flags and context. Gate: none; flags only.
2. **Gather goals and select seeds** — LLM orchestrator with AskUserQuestion (Steps 2 and 2.5). Inputs: user answers, .planning/seeds/SEED-*.md. Outputs: goal list and selected-seed accumulator. Gate: user selection; --auto selects all matches.
3. **Choose version** — LLM (Step 3). Inputs: last heading in MILESTONES.md. Outputs: proposed vX.Y (minor or major bump). Gate: user confirms.
4. **Confirm understanding** — LLM (Step 3.5). Inputs: gathered summary. Outputs: confirmed milestone summary. Gate: user picks Looks good; Adjust loops back.
5. **Update PROJECT.md** — LLM Write (Step 4). Inputs: confirmed summary. Outputs: Current Milestone and Evolution sections in PROJECT.md. Gate: none before the write.
6. **Reset STATE** — gsd-sdk query state.milestone-switch --milestone vX.Y --name (Step 5). Inputs: version and name. Outputs: STATE frontmatter milestone, status planning, zero progress, new Current Position. Gate: STATE lock held by the handler.
7. **Clear old phase directories and commit** — gsd-sdk query phases.clear --confirm, then commit (Step 6). Inputs: all non-999 directories under .planning/phases. Outputs: directories deleted; commit of PROJECT.md and STATE.md only. Gate: none: --confirm is always passed (finding F04).
8. **Load init and agent availability** — gsd-sdk query init.new-milestone and agent-skills (Step 7). Inputs: config, milestone info, agents_installed. Outputs: model ids, phase_dir_count, phase_archive_path. Gate: if agents are missing, research is skipped and the roadmap is written inline.
9. **Reset phase numbers (flag only)** — LLM with mkdir and mv (Step 7.5). Inputs: phase_dir_count, phase_archive_path. Outputs: old phase directories moved to the archive. Gate: stops if no archive path; runs after Step 6 (finding F04).
10. **Research (optional)** — AskUserQuestion; four gsd-project-researcher agents; gsd-research-synthesizer (Step 8). Inputs: PROJECT.md and milestone goals. Outputs: .planning/research/STACK, FEATURES, ARCHITECTURE, PITFALLS and SUMMARY .md. Gate: user choice; not saved to config.json.
11. **Define requirements** — LLM with AskUserQuestion (Step 9). Inputs: research features, seeds, conversation. Outputs: .planning/REQUIREMENTS.md with CATEGORY-NN ids, v1, v2, Out of Scope, empty Traceability; commit 'docs: define milestone v[X.Y] requirements'. Gate: user says yes or adjusts the full list.
12. **Create roadmap** — gsd-roadmapper agent (Step 10). Inputs: PROJECT.md, REQUIREMENTS.md, research SUMMARY, config.json, MILESTONES.md. Outputs: ROADMAP.md phases, STATE.md, Traceability rows; returns ROADMAP CREATED or ROADMAP BLOCKED. Gate: 100 percent requirement coverage; user Approve, Adjust or Review; commit 'docs: create milestone v[X.Y] roadmap'.
13. **Link pending todos** — LLM (Step 10.5). Inputs: .planning/todos/pending and approved ROADMAP. Outputs: resolves_phase in matched todo frontmatter; commit. Gate: clear matches only.
14. **Execute a plan** — execute-plan workflow (update_requirements step). Inputs: PLAN requirements array. Outputs: SUMMARY requirements-completed copied from plan; REQUIREMENTS checkbox and Pending cell flipped by requirements.mark-complete. Gate: plan-checker dimension 1 fails a plan with uncovered requirements.
15. **Phase complete** — gsd-sdk query phase.complete (phase-lifecycle.ts). Inputs: phase number, ROADMAP Requirements line, later directories and headings. Outputs: is_last_phase flag; REQUIREMENTS rows set Complete when Pending or In Progress. Gate: last phase routes to a complete-milestone suggestion (transition Route B).
16. **Audit** — /gsd:audit-milestone [version] (audit-milestone workflow, gsd-integration-checker agent). Inputs: VERIFICATION.md files, SUMMARY frontmatter, REQUIREMENTS.md, VALIDATION files. Outputs: .planning/v{version}-MILESTONE-AUDIT.md with YAML status. Gate: status passed, gaps_found or tech_debt; any unsatisfied requirement forces gaps_found.
17. **Close gaps (only if gaps_found)** — plan-milestone-gaps workflow, or /gsd:phase --insert N per gap. Inputs: audit gaps. Outputs: integer gap phases (highest plus one) or decimal N.M phases; ROADMAP entries; traceability reset to Pending; commit. Gate: user confirms the proposed phases; re-audit after execution.
18. **Pre-close open-artifact audit** — gsd-sdk query audit-open (complete-milestone pre_close_artifact_audit). Inputs: debug, quick, thread, todo, seed, UAT and verification items. Outputs: report; deferred-items record if acknowledged. Gate: Resolve, Acknowledge or Cancel.
19. **Verify readiness** — gsd-sdk query roadmap.analyze and LLM count of checked requirements. Inputs: ROADMAP and REQUIREMENTS. Outputs: phase and requirement summary. Gate: interactive: yes, wait or adjust scope; unchecked requirements: proceed, audit or abort.
20. **Archive** — gsd-sdk query milestone.complete vX.Y --name [--archive-phases]. Inputs: ROADMAP, REQUIREMENTS, audit file, phase directories, STATE. Outputs: milestones/vX.Y-ROADMAP.md, vX.Y-REQUIREMENTS.md, moved audit, MILESTONES.md entry, STATE update, optional vX.Y-phases directory. Gate: phase-directory archive is an optional question; Skip keeps directories in place.
21. **Reorganize ROADMAP and safety commit** — LLM plus git (reorganize_roadmap_and_delete_originals). Inputs: ROADMAP including the 999.x Backlog section. Outputs: grouped ROADMAP with details blocks; commit 'chore: archive vX.Y milestone files'; git rm REQUIREMENTS.md; commit 'chore: remove REQUIREMENTS.md for vX.Y milestone'. Gate: archive files committed before any original is deleted.
22. **Evolve PROJECT.md, retrospective and STATE** — LLM (evolve_project_full_review, write_retrospective, update_state). Inputs: phase SUMMARY files, VERIFICATION and UAT files. Outputs: PROJECT.md Validated, Active, Out of Scope and Key Decisions; RETROSPECTIVE.md section; STATE Project Reference. Gate: checklist in the workflow success criteria.
23. **Branches and git tag** — LLM plus git (handle_branches, git_tag). Inputs: git.branching_strategy, git.create_tag, branch names. Outputs: merged, deleted or kept branches; annotated tag vX.Y if enabled; optional push. Gate: user picks a merge option; push asks yes or no.

## Numbering rules

- Milestone id is v<major>.<minor>, with an optional 1-2 word name; the next id is a minor or major bump chosen by the user. No next-version calculator was found in the files read.
- Integer phase numbers continue across milestones by default. --reset-phase-numbers restarts at 1 after moving old directories (intended behaviour; the step order is defective, see F04).
- Integer phase add uses the max of ROADMAP '### Phase N:' headings and the leading numbers of phase directories, plus one. Numbers 999 and above are ignored; directories zero-pad to two digits.
- Decimal insert after N gives N.M, where M is the highest existing decimal under N plus one. Gaps are not reused. The ROADMAP entry is marked (INSERTED).
- Numbers 999 and above form the backlog range: excluded from numbering, never cleared by phases.clear, and kept in the ROADMAP Backlog section.
- Phase removal applies only to phases after the current phase. Later integer phases and their directories and files move down by one; decimal siblings are renumbered by prefix; executed phases need --force.
- Directory names are NN-slug for integers and NN.M-slug for decimals, with a CODE- prefix when project_code is set. With phase_naming custom, explicit ids such as PROJ-42 are accepted.
- Plan ids are NN-MM (phase, then plan). Requirement ids are CATEGORY-NN and continue numbering within a category.
- Milestone phase membership is the set of 'Phase <id>:' headings in the version's ROADMAP section. Directories match by numeric prefix, custom id or project-code prefix. With no such headings, every directory matches.
- Version strings carry a v prefix in STATE and in code paths (for example v1.0), but the complete-milestone command example writes 1.0. No normaliser was found in the files read.
