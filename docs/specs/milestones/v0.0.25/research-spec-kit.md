## Summary

github/spec-kit at 3b76e6ea (MIT, 143,020 stars) runs an SDD lifecycle built from Markdown slash-command prompts: constitution, specify, optional clarify, plan, tasks, optional analyze, implement, optional converge (repeatable) and optional checklists. Hooks and gates are prose the agent follows; Bash, PowerShell and Python helpers only resolve templates, feature directories and numbering. Features live in specs/NNN-slug or timestamp-prefixed directories, selected through .specify/feature.json, not branch names. Since the Feb 2026 baseline (v0.1.x) it added extensions, presets, a gate-capable workflow engine, bundles, converge and 1.0.0 (2026-08-21). Against Inonu: no milestone folders, no deterministic completion verifier, no decision graph. Static reading only.

## Lifecycle

1. **1 init** — specify init (CLI). Inputs: --integration, optional --preset and --extension. Outputs: .specify tree, agent command files, .specify/init-options.json, seeded constitution. Gate: No gate in code; the mandatory before_constitution git hook runs first when the git extension is installed.
2. **2 constitution** — /speckit.constitution (templates/commands/constitution.md). Inputs: user principles, resolved constitution-template, existing .specify/memory/constitution.md. Outputs: updated constitution with temporary Sync Impact Report and Next Actions for deferred intents. Gate: Scope Guard (lines 21-38), validation pass (121-125), SemVer bump rule (100-104).
3. **3 branch (optional, git extension)** — before_specify hook speckit.git.feature (mandatory). Inputs: git-config branch_numbering, branch_template, branch_prefix, GIT_BRANCH_NAME override. Outputs: git branch NNN-slug or templated name. Gate: mandatory hook must run before specify proceeds (extension.yml 47-50).
4. **4 specify** — /speckit.specify (templates/commands/specify.md). Inputs: feature description, constitution, spec-template. Outputs: specs/<prefix>-<short>/spec.md, .specify/feature.json, checklists/requirements.md. Gate: requirements checklist up to 3 fix iterations (196); at most 3 NEEDS CLARIFICATION markers (128, 201).
5. **5 review-spec (workflow only)** — workflow gate step. Inputs: spec.md. Outputs: choice approve or reject recorded in run state. Gate: reject aborts (workflows/speckit/workflow.yml 46-50).
6. **6 clarify (optional, expected before plan)** — /speckit.clarify (templates/commands/clarify.md). Inputs: spec.md, constitution. Outputs: Clarifications session bullets integrated into spec.md; requirements checklist re-validated. Gate: at most 5 questions, one at a time, stops when answered or user says done (129-141, 175-178); warns if skipped (60).
7. **7 plan** — /speckit.plan (setup-plan.sh copies plan-template). Inputs: spec.md, constitution, plan-template. Outputs: plan.md, research.md, data-model.md, contracts/, quickstart.md. Gate: Constitution Check before and after design; ERROR on violations or unresolved clarifications (plan.md 66-69, 163-164; plan-template 39-43).
8. **8 review-plan (workflow only)** — workflow gate step. Inputs: plan.md. Outputs: approve or reject recorded in run state. Gate: reject aborts (workflows/speckit/workflow.yml 58-62).
9. **9 tasks** — /speckit.tasks (templates/commands/tasks.md). Inputs: plan.md, spec.md, optional data-model, contracts, research. Outputs: tasks.md with Setup, Foundational, one phase per user story, Polish; T### lines. Gate: after_tasks hooks (tasks.md 95-127); test tasks only when requested (147).
10. **10 analyze (optional, read-only)** — /speckit.analyze (templates/commands/analyze.md). Inputs: spec.md, plan.md, tasks.md, constitution. Outputs: Markdown report with IDs, severities and coverage table; no file writes. Gate: CRITICAL for constitution MUST violations; advised to resolve before implement (56-60, 157, 196).
11. **11 checklist (optional)** — /speckit.checklist (templates/commands/checklist.md). Inputs: domain request plus spec, plan, tasks. Outputs: checklists/<domain>.md with CHK items, all unchecked. Gate: generator must not mark items [x] (checklist.md 30-37).
12. **12 implement** — /speckit.implement (templates/commands/implement.md). Inputs: tasks.md, plan.md, optional design docs, checklists. Outputs: code, ignore files, tasks marked [X]. Gate: stops and asks if any checklist item is unchecked (79-84); halts on failed non-parallel task (165).

## Numbering rules

- Core sequential number is the highest 3-plus-digit prefix among specs/ subdirectories plus one, zero-padded to three digits; timestamp-shaped directories are excluded from the scan (scripts/bash/create-new-feature.sh 112-134, 382).
- Git extension next number is the maximum of highest local branch number, highest remote head number (git ls-remote, unless skipped) and highest spec directory number, plus one (extensions/git/scripts/bash/create-new-feature-branch.sh 185-205).
- Timestamp mode uses YYYYMMDD-HHMMSS in place of the number; --number is ignored with a warning in that mode (create-new-feature.sh 349-358).
- An explicit --number is a preference; if its prefix already exists in specs/, the script corrects it automatically (create-new-feature.sh 384-405).
- Branch name is {number}-{slug} by default, or built from branch_template or branch_prefix (create-new-feature-branch.sh 349-375); the whole name is capped at 244 bytes by trimming the suffix (create-new-feature.sh 97-98, 228-255).
- GIT_BRANCH_NAME, when set, replaces the whole branch name and bypasses prefix and suffix generation (create-new-feature-branch.sh 495-497; specify.md 78).
- Spec directory name and git branch name are independent; the directory is the feature identity (specify.md 108-111).
- Feature resolution precedence is SPECIFY_FEATURE_DIRECTORY, then .specify/feature.json, then an error; CURRENT_BRANCH falls back to the directory basename (scripts/bash/common.sh 186-224).
- Numbering mode precedence is git-config branch_numbering, then init-options feature_numbering, then deprecated init-options branch_numbering, then sequential (speckit.git.feature.md 31-36; specify.md 86-92).
- Identifiers: US1..USn with P1..Pn priorities, FR-###, SC-###, T### tasks with optional [P] and [USn], CHK### checklist items, Q1..Q3 for spec questions, analyze finding IDs prefixed by category initial (tasks.md 154; checklist-template.md 27; analyze.md 172).

## Adoption candidates (reader's)

- **Append-only convergence pass for milestone tasks** (effort M; relates to F17, F16, F18, F01). Adopt: Adopt the converge contract: a re-assessment that may only append one Convergence section to tasks.md, leaves the file byte-identical when every requirement is met, and stops when spec, plan or tasks are missing. Assessment reads code and checks, not completion claims. In Inonu: A new subcommand of the SDD artifact audit (stdlib only), for example sdd converge: hash the existing task lines before and after, fail if any pre-existing line changes, map each R-id in spec.md to a task or a passing loop-runner check, then append a block or write nothing.
- **Reviewer-owned checklist marks** (effort S; relates to F14, F18). Adopt: Only a reviewer may mark a requirements-quality item done. The generator writes unchecked items and never flips a box; checked items carry reviewer and date. In Inonu: Audit rule: a checked item without a reviewer record in the file header fails the audit. A unit test asserts the generator code path writes only unchecked lines.
- **Hard budget on open questions** (effort S; relates to F15, F14). Adopt: Clarification caps open questions (3 spec markers, 5 questions per session, one at a time) and requires one recommended option with a why line. In Inonu: The audit counts NEEDS CLARIFICATION markers in spec.md and fails above 3. The Jev brief builder refuses more than 5 open decisions per scope choice and requires one recommended option with evidence. Jev recommends; the deterministic gate decides.
- **Explicit pointer for the active milestone** (effort S; relates to F02, F23). Adopt: Select the active milestone by pointer instead of branch name: environment override, then a pointer file, then an error. The branch name is only a label.
