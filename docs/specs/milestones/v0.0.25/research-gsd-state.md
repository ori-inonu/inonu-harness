## Summary

GSD keeps project memory as markdown in .planning/: PROJECT, REQUIREMENTS, ROADMAP, STATE, config.json, MILESTONES, per-phase files and milestone archives. STATE.md's body is authoritative; its frontmatter is re-derived on every write. Deprecated gsd-tools.cjs and gsd-sdk query expose state, phase, roadmap, milestone, verify, frontmatter, commit, config and init commands. Context survives a cleared session through STATE.md (read first), a pause that writes HANDOFF.json and .continue-here.md as a WIP commit, and a resume that ranks them. Writes use lockfiles, but the planning lock force-breaks live holders after 10 seconds. Against Inonu, GSD has no revision or as-of replay; its strength is git-tracked per-phase artifacts. Static reading only.

- **F03** (state, seen, supported) **STATE.md body is authoritative; frontmatter is re-derived on every write.** buildStateFrontmatter reads body fields (Current Phase, Status, Progress, Last Activity, Stopped At, Paused At), takes the milestone from getMilestoneInfo, and counts phase and plan files on disk, cached per process. It emits gsd_state_version 1.0, milestone, milestone_name, current_phase, current_phase_name, current_plan, status (normalized to paused, executing, planning, discussing, verifying, completed or unknown), stopped_at, paused_at, last_updated, last_activity and a progress map (total and completed phases and plans, percent). writeStateMd and readModifyWriteStateMd call syncStateFrontmatter before every write, so hand edits to the derived frontmatter are overwritten, except the progress block on the non-resync path. Evidence: `get-shit-done/bin/lib/state.cjs` 749-765, 860-882, 992-1003, 1024-1052; `get-shit-done/bin/lib/state-document.generated.cjs` 65-90.
- **F04** (state, seen, supported) **Body fields are read and replaced by first-match regex.** stateExtractField tries a bold Field: pattern first and then a plain Field: line anchored at line start. stateReplaceField replaces only the first match because its regex has no global flag. A label repeated in history prose is therefore hit by the first match. Only Stopped At extraction is scoped to the Session section (bug 2444 comment); every other field searches the whole body. The same parser serves state commands, phase complete and begin-phase, so a duplicated label anywhere in STATE.md can redirect writes. Evidence: `get-shit-done/bin/lib/state-document.generated.cjs` 29-51; `get-shit-done/bin/lib/state.cjs` 756-765.
- **F05** (state, seen, supported) **STATE.md writes use an O_EXCL lockfile that never breaks a live holder.** acquireStateLock creates STATE.md.lock with O_EXCL and writes its pid. It retries transient filesystem errnos (EPERM, EBUSY, EAGAIN, EINTR, EINVAL, EIO, ENOENT, ESTALE). A lock is removed only when its mtime is older than 10 seconds. A live lock is waited on for up to 30 seconds and then the call throws. readModifyWriteStateMd holds the lock across read, transform and write, which prevents lost updates when parallel executors touch STATE.md. An exit handler removes held locks. Evidence: `get-shit-done/bin/lib/state.cjs` 27-38, 922-980, 992-1003, 1024-1052.
- **F06** (state, seen, supported) **The planning lock force-breaks live holders after 10 seconds.** withPlanningLock guards ROADMAP and REQUIREMENTS edits (phase add, phase complete and others) with .planning/.lock. It retries in 100 ms steps for up to 10 seconds, and a lock older than 30 seconds is removed. When the timeout is reached the code unlinks the lock unconditionally and runs the critical section, even if a live process still holds it. The STATE lock refuses to break a live lock (F05), so the two helpers disagree. Impact is inferred: a critical section longer than 10 seconds can overlap another writer and lose ROADMAP or REQUIREMENTS updates. Evidence: `get-shit-done/bin/lib/planning-workspace.cjs` 248-307; `get-shit-done/bin/lib/phase.cjs` 584, 1119-1120; `get-shit-done/bin/lib/state.cjs` 922-980.
- **F07** (state, seen, supported) **Frontmatter set and merge are unlocked read-modify-write.** cmdFrontmatterSet and cmdFrontmatterMerge read the file, mutate the parsed object and write it back with platformWriteSync. Neither takes a lock, unlike writeStateMd. set coerces the value with JSON.parse and falls back to the raw string, so 123 becomes a number and true a boolean. reconstructFrontmatter silently skips any key whose value is null or undefined, so setting a key to null removes it on the next rewrite. Evidence: `get-shit-done/bin/lib/frontmatter.cjs` 121-127, 336-364.
- **F08** (workflow, seen, supported) **Pause writes a JSON handoff and a markdown handoff, then commits them as WIP.** pause-work picks the handoff path from the detected work type (phase, spike, sketch, deliberation, research or default). It gathers position, completed and remaining tasks, blockers, human actions pending, background processes, uncommitted files and blocking constraints with a severity. It writes .planning/HANDOFF.json (version 1.0, status paused, next_action, context_notes) and the markdown .continue-here.md with frontmatter (context, phase, task, total_tasks, status, last_updated) and a blocking-constraints checklist. Both are committed with gsd-sdk query commit using a wip message. The pause flow makes no STATE.md update. Evidence: `get-shit-done/workflows/pause-work.md` 11-38, 40-63, 65-106, 108-141, 204-213.

The continue-here template says the file is deleted after resume, but resume-project, execute-phase, execute-plan, discuss-phase and transition never remove it. execute-phase and discuss-phase run a mandatory check before any other work: a .continue-here.md with blocking anti-pattern rows requires three written answers. - **F12** (state, seen, supported) **Pause does not update STATE.md session continuity.** The STATE template defines Session Continuity fields (Last session, Stopped at, Resume file). state.cjs record-session writes them, and the executor calls state.record-session after each plan. The pause workflow calls only current-timestamp and commit. A pause therefore leaves STATE.md describing the last executor run, while HANDOFF.json and .continue-here.md describe the pause point. Resume reads both, so they can disagree. Impact is inferred. Evidence: `get-shit-done/templates/state.md` 77-81; `get-shit-done/bin/lib/state.cjs` 589-625; `agents/gsd-executor.md` 681-685; `get-shit-done/workflows/pause-work.md` 69, 210.
- **F13** (milestone, seen, supported) **Milestone identity is read from STATE.md first, then from ROADMAP markers.** getMilestoneInfo prefers the milestone field in STATE.md frontmatter and looks up its name in ROADMAP.md, either in a heading or in an in-progress list marker. A heading containing a shipped check mark is skipped so detection falls through to the active milestone. Shipped sections are removed from parsing by <details> stripping, or the current version is found by positive lookup. Versions are free strings: new-milestone suggests the next minor version from the last MILESTONES.md entry (v1.0, v1.1, v2.0). The Inonu v0.0.N scheme is not used. Evidence: `get-shit-done/bin/lib/core.cjs` 919-921, 939-960, 1599-1646; `get-shit-done/workflows/new-milestone.md` 98-101.

- **F15** (command, seen, supported) **phases clear --confirm deletes every phase directory, and new-milestone runs it.** cmdPhasesClear removes every top-level phase directory except 999.x backlog entries, using a recursive forced rmSync. - **F19** (workflow, seen, supported) **execute-phase post-merge guard runs git reset --hard and git rm on the orchestrator branch.** For each worktree branch, execute-phase copies STATE.md and ROADMAP.md, skips any worktree whose branch has deletions, merges the branch with --no-ff, and restores both files from the backup. ## Lifecycle

1. **1 new-project** — /gsd:new-project workflow with project-researcher, research-synthesizer and roadmapper agents; init.new-project. Inputs: user answers, optional source document. Outputs: PROJECT.md (commit docs: initialize project); config.json via config-new-project (commit chore: add project config); REQUIREMENTS.md (commit docs: define v1 requirements); ROADMAP.md and STATE.md written by gsd-roadmapper. Gate: user confirms Create PROJECT.md (new-project.md 370-380); config defaults from the manifest.
2. **2 discuss-phase N** — discuss-phase workflow. Inputs: ROADMAP phase block, REQUIREMENTS.md, prior phase CONTEXT. Outputs: NN-CONTEXT.md, DISCUSSION-LOG; DISCUSS-CHECKPOINT.json during the run, removed on finish. Gate: blocking anti-pattern check on .continue-here.md (discuss-phase.md 153-159).
3. **3 plan-phase N** — gsd-planner agent with plan checker; init.plan-phase. Inputs: CONTEXT.md, RESEARCH.md, REQUIREMENTS.md, ROADMAP phase. Outputs: NN-MM-PLAN.md with wave, depends_on, files_modified, autonomous, requirements and must_haves frontmatter. Gate: plan checker agent (not read in detail); frontmatter validate --schema plan checks key presence.
4. **4 execute-phase N** — execute-phase workflow; state.begin-phase; one gsd-executor per plan, optionally in worktrees. Inputs: PLAN files, CONTEXT, prior SUMMARY files. Outputs: per-task commits; NN-MM-SUMMARY.md with Self-Check; STATE via advance-plan, update-progress, record-metric, add-decision, record-session; ROADMAP via roadmap.update-plan-progress. Gate: blocking anti-pattern check (execute-phase.md 193-215); post-merge guard (760-815); verify-summary spot check.
5. **5 verify** — gsd-verifier agent. Inputs: all PLAN, SUMMARY, CONTEXT files and REQUIREMENTS.md. Outputs: NN-VERIFICATION.md with status and overrides. Gate: debt-marker gate sets gaps_found (gsd-verifier.md 442); human_needed is only a warning at phase complete (phase.cjs 1111-1115).
6. **6 phase complete N** — phase.cjs cmdPhaseComplete via gsd-sdk query phase complete. Inputs: ROADMAP.md, REQUIREMENTS.md, STATE.md, phase directory. Outputs: ROADMAP checkbox and progress row with date; REQUIREMENTS entries marked complete; STATE updated under lock. Gate: phase must exist on disk (phase.cjs 1088-1091); UAT and VERIFICATION issues are warnings only (1097-1116).
7. **7 pause** — pause-work workflow (command /gsd:pause-work). Inputs: STATE.md, phase directory, git status, executor notes. Outputs: .planning/HANDOFF.json; phase or fallback .continue-here.md; WIP commit via gsd-sdk query commit. Gate: blocking constraints must be listed with severity; checklist before finishing (pause-work.md 238-239).
8. **8 resume** — resume-project workflow (command /gsd:resume-work) and gsd-sdk query init.resume. Inputs: STATE.md, PROJECT.md, HANDOFF.json, .continue-here files, PLANs without SUMMARY, .planning/current-agent-id.txt. Outputs: status block; HANDOFF.json deleted after successful resume (resume-project.md 101); route to the next workflow. Gate: user picks next action; blocking anti-pattern understanding check on the resumed phase (execute-phase.md 193-215).
9. **9 new-milestone** — new-milestone workflow; state.milestone-switch; phases.clear --confirm; commit. Inputs: MILESTONES.md last version, PROJECT.md, user milestone name. Outputs: STATE frontmatter milestone fields reset and body Current Position rewritten; leftover phase directories deleted; commit docs: start milestone. Gate: explicit --confirm flag on phases clear (milestone.cjs 283-295); no interactive check in the CJS path.
10. **10 complete-milestone** — complete-milestone workflow; audit-open; roadmap analyze; milestone complete (archive). Inputs: ROADMAP.md, REQUIREMENTS.md, SUMMARY files, open-artifact audit. Outputs: milestones/vX.Y-ROADMAP.md, vX.Y-REQUIREMENTS.md, vX.Y-MILESTONE-AUDIT.md, optional vX.Y-phases/; MILESTONES.md entry; deferred items in STATE; annotated git tag v[X.Y]. Gate: audit-open acknowledgement (complete-milestone.md 44-74); unmet requirements need a Proceed anyway choice (126-130); tag only when create_tag is set.

## Artifacts

- `.planning/PROJECT.md` — project context, validated, active and out-of-scope requirements, key decisions table Format: markdown with fixed H2 sections.
- `.planning/REQUIREMENTS.md` — REQ-ID checklist (CATEGORY-NN) and traceability table, marked complete by requirements mark-complete Format: markdown checkboxes and table.
- `.planning/ROADMAP.md` — phase checklist, per-phase goal, depends-on, requirements, success criteria and plan count; progress table Format: markdown; parsed by regex on Phase N headings.
- `.planning/STATE.md` — current position, progress bar, velocity metrics, decisions, blockers, deferred items, session continuity Format: markdown bold field labels plus derived YAML frontmatter (gsd_state_version 1.0).

## Numbering rules

- Phase directories are NN-slug with two-digit zero padding (phase.cjs 630-631); with project_code set they become CK-01-slug (phase.cjs 588-590, 631).
- Sequential mode takes the max of ROADMAP Phase N headings and on-disk NN- prefixes, ignoring numbers 999 and above, which are backlog (phase.cjs 604-610, 619-625).
- Decimal phases N.M are inserted between integers, numbered from a directory and roadmap scan (phase.cjs 148-210, 739-831).
- phase_naming custom takes an explicit --id and skips auto-increment (phase.cjs 595-599).
- Plan IDs are NN-MM; files are NN-MM-PLAN.md and NN-MM-SUMMARY.md (templates/phase-prompt.md line 8).
- Requirement IDs are CATEGORY-NN checkboxes such as AUTH-01 (templates/requirements.md 19-22).
- Milestone versions are free strings, conventionally v[X.Y]; new-milestone suggests the next minor version from MILESTONES.md (new-milestone.md 98-101); git tags are annotated vX.Y and archive files reuse the same version string (milestone.cjs 163-176).
