## Summary

GSD (gsd-build/get-shit-done, MIT, HEAD bdcaab2c) ships 67 slash commands as thin prompts in commands/gsd/*.md. Each loads one of 88 workflow files and may spawn some of 33 agent roles. Project state lives in .planning/ (PROJECT, config.json, STATE, ROADMAP, REQUIREMENTS, then per-phase CONTEXT, PLAN, SUMMARY, VERIFICATION). A milestone closes through audit-milestone, then complete-milestone (archive, retrospective, annotated tag), then new-milestone, which keeps phase numbers unless reset. Most gates are instructions the model follows; the code-enforced ones are shell exit codes, git-log checks and SDK handlers (gsd-sdk query). Static reading only; nothing was run.

## Findings

- **F01** (command, seen, supported) **67 command files share one frontmatter pattern.** Each file in commands/gsd/ is a markdown prompt with YAML frontmatter: name (gsd:<cmd>), description, argument-hint, allowed-tools and optionally requires (a list of other commands) or type: prompt. The tree at HEAD holds 67 such files, matching the count in docs/INVENTORY.md. ## Numbering rules

- Phase numbers are integers; they continue across milestones by default and restart at 1 only with --reset-phase-numbers, which is refused until the previous milestone is archived (workflows/new-milestone.md lines 25, 244-262, 461, 482).
- Urgent work is inserted as a decimal phase (for example 72.1) between existing phases through /gsd:phase --insert (commands/gsd/phase.md routing table).
- Phase directories are named XX-name under .planning/phases/ (templates/continue-here.md example uses 02-authentication).
- Plan identifiers are <phase>-<plan> with a zero-padded plan number (CURRENT_PLAN_ID is phase_number-plan_padded, workflows/execute-phase.md line 168); the summary file is <plan_padded>-SUMMARY.md inside the phase directory.
- The review file is <PADDED phase>-REVIEW.md where PADDED is the phase number formatted with two digits (workflows/execute-phase.md code_review_gate, lines 1217-1222 region).
- Milestone versions are v1.0 for the first release, v1.1 for a minor step and v2.0 for a major step (workflows/new-milestone.md line 101); archive files use v[X.Y] and the git tag is v[X.Y].
- Commit subjects follow conventions the gates read: test(<phase>-<plan>): marks RED commits (workflows/execute-phase.md line 184 regex), chore: remove REQUIREMENTS.md for vX.Y milestone closes a milestone, and feat(XX-XX) to feat(YY-YY) denotes a milestone git range (templates/milestone.md).
- Requirement IDs are REQ-IDs grouped by category with checkboxes in REQUIREMENTS.md (workflows/new-milestone.md line 413); the verifier cross-references them against plan frontmatter.
- Debug sessions are named by slug at .planning/debug/<slug>.md; quick tasks sit in .planning/quick/ with their own slugs (commands/gsd/debug.md, commands/gsd/quick.md).
