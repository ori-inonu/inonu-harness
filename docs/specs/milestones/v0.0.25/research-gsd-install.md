## Summary

GSD ships as one npm package, get-shit-done-cc (version 1.50.0-canary.0, MIT, Node 22 or later). bin/install.js writes commands, skills, agents, hooks and settings into 15 supported runtime config directories, globally or locally, and records a sha256 manifest of every file it owns. Before overwriting, it copies locally changed files to gsd-local-patches/ with pristine copies for a later three-way merge run by /gsd-update --reapply. Hooks are built from hooks/dist, stamped with the package version and registered with absolute runner paths. Uninstall removes files by name and filters settings entries, but leaves patch, pristine and migration state behind. Updates run as the /gsd-update workflow through npx. Static reading only; nothing was executed.

## Lifecycle

1. **1. Resolve runtimes and scope from argv or prompts** — User runs npx -y get-shit-done-cc@latest with runtime and scope flags, or node bin/install.js; main dispatch in bin/install.js. Inputs: argv flags, TTY state, GSD_TEST_MODE. Outputs: selectedRuntimes list and isGlobal flag. Gate: Exactly one of --global or --local; --config-dir not with --local; --uninstall needs a scope (bin/install.js 11340-11350). No TTY and no flags installs Claude globally (11366-11368)..
2. **2. Plan and apply installer migrations before package writes** — install() calls runInstallerMigrations with baselineScan (bin/install.js 8212-8219). Inputs: gsd-file-manifest.json, gsd-install-state.json, migrations folder, package version. Outputs: Journal under gsd-migration-journal/, rollback and backup folders, updated install state. Gate: Migration lock (installer-migrations.cjs 260-304); checksum check (158-186); non-TTY auto-resolution with classifier and env override (bin/install.js 8220-8235); blocked prompt-user actions stop the install.
3. **3. Capture locally modified managed files** — saveLocalPatches called from install() (bin/install.js 8025-8030). Inputs: Old manifest and on-disk file hashes. Outputs: gsd-local-patches/<rel> copies, backup-meta.json, gsd-pristine/<rel> baseline when modified files exist. Gate: No manifest means no detection (7683); only manifest keys are compared; path checks reject absolute, dot and symlink paths (7413-7466).
4. **4. Copy layout content, GSD payload and agents** — installRuntimeArtifacts (8294), get-shit-done/ copy (8431-8434), commands/gsd copy (8389-8406), agents (8515-8594), CHANGELOG and VERSION (8604-8622). Inputs: Package source dirs, runtime layout table, converters. Outputs: Runtime-specific tree (skills, commands, agents, get-shit-done/). Gate: verifyInstalled and verifyFileInstalled record failures (7343-7380).
5. **5. Copy hooks from hooks/dist and hooks/lib and stamp versions** — install() hook block (bin/install.js 8633-8723). Inputs: hooks/dist built by scripts/build-hooks.js; hooks/lib helpers. Outputs: configDir/hooks/gsd-*.js|sh and hooks/lib files with version headers. Gate: Missing hooks/dist records a failure (8699-8709); missing .sh hooks warn (8702-8704); Codex copies only gsd-check-update.js (8987-8990).
6. **6. Write the manifest and report patches** — writeManifest then reportLocalPatches (bin/install.js 8737-8741). Inputs: Installed files on disk. Outputs: gsd-file-manifest.json with sha256 per file; console report of backed-up patches. Gate: Manifest is written after content copy, so an earlier failure leaves the old manifest (inferred).
7. **7. Register runtime config and hooks** — Runtime branches in install() (bin/install.js 9025-9120 for Codex; 9204-9600 for settings.json runtimes). Inputs: settings.json or config.toml and hooks.json, absolute runner paths. Outputs: Hook entries (SessionStart, PostToolUse or AfterTool, PreToolUse or BeforeTool), statusLine, Codex managed blocks. ## Numbering rules

- package.json version is semver with a pre-release suffix; the current value is 1.50.0-canary.0 (package.json line 3).
- Release tiers: patch x.y.Z ships from a hotfix/x.y.z branch to dist-tag latest; minor ships rc.N to next and is promoted to latest; major ships beta.N to next and is promoted to latest (VERSIONING.md 7-11, 53-59).
- One pre-release type per version: rc for minor, beta for major (VERSIONING.md 41-43).
- Users get pre-releases only through the next dist-tag (VERSIONING.md 19-22).
- Installer migration ids are date-prefixed slugs such as 2026-05-11-legacy-orphan-files; introducedIn holds the package version (001 file lines 9, 12; 002 file line 54; 000 file line 146).
- A migration whose checksum changed keeps its id only if the change is refused; fixes ship under a new id (docs/installer-migrations.md 124-126).
- Hook files are named gsd-<purpose>.js or .sh and carry a gsd-hook-version header stamped at install (bin/install.js 8660).
- Profile names are core, standard and full; several can be composed with commas (install-profiles.cjs 15, 58-88).
