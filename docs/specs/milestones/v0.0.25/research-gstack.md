## Summary

gstack (garrytan/gstack, MIT, HEAD 576839c) is a Claude Code skill pack run as a sprint: Think, Plan, Build, Review, Test, Ship, Reflect. Skills are .tmpl sources that generate committed SKILL.md files. State lives under ~/.gstack in per-project buckets for learnings, timelines, design docs and checkpoints. Safety comes from PreToolUse hooks (careful, freeze, guard). Release mechanics: a version is stamped per merge, merge trains gate several PRs with one full gate, and a weekly cut tags a stable branch. Unattended /autoplan runs write hashed manifests and one result line. No path named milestone exists; the closest analogs are fix-wave docs, trains and run directories. Static reading only.

## Lifecycle

1. **1. Install** — user runs git clone into ~/.claude/skills/gstack, then ./setup (or ./setup --team). Inputs: checkout at HEAD; Bun 1.3.3 or newer; Node.js on Windows. Outputs: skills and hooks registered in host directories; bundled browser build; state root created. Gate: setup exit status; ./setup --status rows; gstack-doctor readiness.
2. **2. Think** — /office-hours. Inputs: problem statement; prior design docs found by glob and keyword grep under projects/<slug>. Outputs: projects/<slug>/*-design-*.md design doc; builder profile entry. Gate: hard gate: no implementation; stops for approval of the chosen approach; DESIGN_DOC file check before telemetry.
3. **3. Plan (strategy)** — /plan-ceo-review, or /autoplan phase 1. Inputs: design doc; repo context. Outputs: reviewed plan with a chosen mode (expansion, selective expansion, hold scope, reduction). Gate: user picks mode; autoplan records taste decisions for the final gate.
4. **4. Plan (design, DX, eng)** — /plan-design-review, /plan-devex-review, /plan-eng-review (autoplan runs eng last). Inputs: plan. Outputs: amended plan and test plan (README claim). Gate: one question per design choice; unattended runs write approval items instead of asking.
5. **5. Final approval (autoplan only)** — gstack-gate render of gate.json. Inputs: run directory with decisions, findings, tasks. Outputs: gate_pending run; nothing approved by the tool. Gate: owner reply parsed against gate revision; bare yes or no refused.
6. **6. Build** — host agent, optionally with /careful, /freeze or /guard active. Inputs: tasks and plan. Outputs: commits on a feature branch. Gate: freeze boundary denies out-of-scope edits; careful asks before destructive commands.
7. **7. Review** — /review (also invoked inside /ship at Steps 9 and 11). Inputs: diff against merge base; checklist; specialist reviewers. Outputs: AUTO-FIX edits, batched ASK items, review-log rows, deferred issues. Gate: only CRITICAL findings block; three-pass cap in ship; NO FINDINGS is a complete result.
8. **8. Test** — /qa, /qa-only, /investigate, /benchmark, /eval-plan. Inputs: running app or CLI; bug report; eval plan. Outputs: QA report; regression tests; eval dry-run.json. Gate: investigate stops after three failed fixes (README); priced eval steps need approval.
9. **9. Ship** — /ship, Steps 0.9 to 22. Inputs: branch, base, VERSION, CHANGELOG, invocation record. Outputs: version stamp and CHANGELOG (Step 12); commit (15); verified frozen tree (16); push and PR (17 to 19); ship receipt bound to HEAD; result line. Gate: Step 16 five stages; review gates at Steps 9 and 11.5; receipt must name the pushed head before the queue accepts it.
10. **10. Queue or train** — /captain, or gstack-ship-queue ready, stamp, verify, train. Inputs: READY blocks with head SHA from lanes. Outputs: stamped heads; train/<nonce> branches and refs/notes/gstack-trains records (only when the policy has a train block). Gate: one full gate on train head; verify --train before each merge; merge pinned to the expected head.
11. **11. Land and deploy** — /land-and-deploy, then /canary. Inputs: approved PR; deploy settings from /setup-deploy. Outputs: merged PR; production health and monitoring output. Gate: CI and deploy checks (not read in this pass).
12. **12. Weekly release** — .github/workflows/weekly-release.yml (cron Monday 14:00 UTC, or manual dispatch with a SHA). Inputs: newest green commit on main; CHANGELOG entries since last release. Outputs: annotated tag v<VERSION>; GitHub Release; stable fast-forwarded. Gate: free-tests and main-backstop check runs green; no active train freeze; stable only moves forward.
13. **13. Reflect** — /retro, /learn, /document-release. Inputs: git log; timeline; learnings; .context/retros snapshots; skill usage log. Outputs: retro snapshot JSON and narrative; learnings added or pruned; documentation audit result. Gate: /learn is manage-only, no code changes; /retro writes only its snapshot.
